## Second integrated implementation checkpoint

This continuation reconstructs the previously unpersisted fixes on top of
`f45d2b46bd4768d16b25c86330dcff55b6d80e43`; it does not claim that an unavailable
old working directory was recovered. All changes are being published through
the existing PR #151. The final acceptance must name the resulting commit.

Implemented and locally checked:

- Billing owns durable, idempotent Subscription period funding claims. Refund
  commands and database enforcement share the credit fence; cancellation has
  an irreversible tombstone and a recoverable release queue.
- Subscription renewal creates a fresh purchase, quote, obligation and period.
  Customer recovery binds the exact subscription and period and cannot locally
  extend expiry, activate a purchase or create a second payment after an unknown
  outcome. Admin can inspect failed release attempts and request an audited,
  revision-bound retry without issuing a refund.
- Communications and Reporting consume the native events actually emitted by
  Booking/Dispatch/Workforce. Cancellation suppresses pending/retried booking
  notifications and keeps evidence of in-flight attempts. A technician's cash
  declaration never becomes a Billing payment projection.
- Admin and Operator fence in-flight reads, refreshes and multi-step writes to
  the current session. Clearing a session removes private screens, modal DOM,
  upload state, retry state and transient text. Customer already keys private
  sheets and recovery to the Identity session/account.
- Identity has an audited, one-shot initial administrator CLI. It only promotes
  an existing active account with persisted successful OTP/login evidence;
  it revokes old sessions and cannot be reused after later role changes.
- The migration image now uses the pinned minimal Debian 13 runtime plus the
  native libraries Prisma needs. Its unfiltered scan remains mandatory and
  requires execution proof from that exact image. The shared internal transport
  policy permits Railway HTTP only for explicitly allowed private hosts within
  a configured project/environment; external provider endpoints remain HTTPS.
- Cross-owner browser harnesses now live under root acceptance tests. The
  ownership guard excludes only a workspace's compiler-generated `dist-tests`
  directory and still rejects authored cross-owner imports.

Observed local owner evidence is recorded in the finance/runtime handoffs.
