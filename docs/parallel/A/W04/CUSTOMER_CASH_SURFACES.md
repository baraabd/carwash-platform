## Durable list, detail and update requirements

1. Booking/C owns order list/detail/status projections and immutable booking snapshots; B supplies authoritative cash receipt/correction/payment facts; Wallet/B custody/reconciliation refs remain independent; Media/C object authorization controls private images. Gateway and app own transport/presentation only.
2. Query scope binds member/guest beneficiary, approved market/visibility, filter and cursor generation. Define deterministic accepted order, stable tie-breaker, bounded page size and cursor expiry; deduplicate IDs without losing newer revisions. Loading, empty, error, partial and stale differ.
3. Active/past totals and navigation badge are authoritative for the same filter/snapshot/as-of, not `loadedPage.length`. Completed-but-uncollected classification, canceled/failed buckets and default ordering require policy. Reconnect or status move between buckets updates totals/cards/Home without duplicates or stale counts.
4. Lists and detail links read immutable server vehicle/address/contact/catalog/money/time snapshots. Deleting/editing saved records or repricing current catalog does not rewrite order history or Billing receipt. Rebook creates a new draft and revalidates current facts; no old paid state/slot is reused.
5. Deep-link reads independently authenticate/authorize member or actual guest access; URL IDs/phone/scenario are no authority. Absent versus unauthorized response disclosure follows accepted policy. Route method mismatch still shows source truth; a cash PaymentRoute never creates QR or collection action.
6. Status versions are **per authoritative aggregate/source**, with approved projection generation/coverage. Drop duplicates/older versions, detect equal-version different payload/gaps and resynchronize from owned snapshot. Do not compare Booking/Dispatch/Billing/Media revisions as one counter or make a cash event advance Work.
7. Reconnect/resume/page visibility refresh against accepted cursor/checkpoint; bounded polling/backoff is fallback to accepted update transport. Drop responses after principal/filter/order/generation changes. Older list/detail/media replies cannot overwrite fresher state; cancellation/reassignment cannot be resurrected by late events.
8. Stale/unavailable source retains its last known value with approved freshness label or hides it; absence is never zero cash, settled money or completed work. No worker/live location is displayed without current grant and approved precision/contact projection.
9. Collection is operator/B-authorized and treasury reconciliation D/B-authorized. Unknown outcome after response loss queries/replays the same durable operation; collection business identity also deduplicates changed-key retries. Customer routes are read-only for collection, handover, work progression and merchant settings.
10. Present Gateway blocks query strings in [routeMatch](https://github.com/baraabd/carwash-platform/blob/1ec9d8aebf4470a2815471116643fa6ebe0d5a95/apps/api-gateway/src/domain/policy.ts#L22); [verifiedHeaders](https://github.com/baraabd/carwash-platform/blob/1ec9d8aebf4470a2815471116643fa6ebe0d5a95/apps/api-gateway/src/application/gateway.service.ts#L86) omits conditional headers and maps status>=300 (including304) to a fault; [HTTP client](https://github.com/baraabd/carwash-platform/blob/1ec9d8aebf4470a2815471116643fa6ebe0d5a95/apps/api-gateway/src/infrastructure/http-client.ts#L6) buffers bounded JSON. E must accept cursor/filter/query, conditional read/version and update/media transport adapters; current JSON routing is not SSE/WS/private-image support.
