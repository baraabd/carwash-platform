## Serialized candidate protocol

1. Refresh accepted base/packages/owner registry and real producer evidence;
   establish all matrix rows and decisions. Obtain the authoritative prior
   40-package list. Unresolved required rows or provider/design inputs block
   full scope. Record latest target full SHA/tree and exact PR head/tree/reviews.
2. Construct an isolated candidate from those two immutable refs through the
   authorized integration process. Bind candidate full SHA/tree/ordered
   parents, exact dependency/configuration versions and every changed path.
   If either target or head moves, recompute the candidate and applicable gates.
3. Run every mandatory CI job and all affected real acceptance families. Bind
   retained commands/results/run IDs/attempts/logs/artifact SHA256 to that exact
   candidate. A skipped/blocked/mocked case cannot become PASS. Local scope and
   design guards supplement required checks; they do not replace them.
4. Obtain eligible independent review and protected approval. Multiple sessions
   using the same login do not create independent approval. No self-approval,
   weakened branch rules, automatic merge or deployment is authorized here.
5. Recheck refs/reviews/checks immediately before the authorized merge; then
   verify the actual resulting target's mandatory and affected checks. A
   head/candidate or different same-tree commit is not that target's CI record.
6. Publish a wave base only after the real complete combined acceptance and
   existing-staging evidence are accepted. A later source/config/evidence
   commit requires applicable checks again. Do not publish BASE_W08 from this
   proposal, foundation-only CI, partial methods or pending review.
