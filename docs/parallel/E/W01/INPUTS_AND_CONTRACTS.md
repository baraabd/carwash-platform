### Existing Identity and Gateway capability

`services/identity/src/transport/http/auth.controller.ts` implements JWKS, CSRF, register/login challenge issuance, challenge resend/verification, session read, read-only command authorization, refresh, logout/logout-all and authorized account status/role changes. Input keys are explicitly validated. Account/session/refresh/challenge/audit state is real Identity-owned persistence, with a separate migration history. The role vocabulary is Customer, Technician, Operations, Finance, Support, Reviewer and Super Admin; callers must use the exact lowercase contract values.

The current OTP delivery adapter sends a webhook payload with `channel: 'email'`. Challenge acknowledgement expressly does not assert email or SMS delivery. Guest-booking authorization is not implemented by the existing authenticated routing contract. W02 must extend the existing Identity capability with a reviewed guest/ownership contract; it must not fabricate an authenticated user or replace Identity with demo login.

Gateway verifies signed credentials and live Identity session state on each protected request; cookie commands also use Identity-owned CSRF authorization. Domain owners independently verify credentials and object ownership. Gateway-derived actor headers are metadata. Business command idempotency is delegated to owners; Gateway does not retry unknown command outcomes or own the durable business state.
