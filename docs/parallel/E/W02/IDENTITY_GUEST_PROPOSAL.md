Candidate design constraints for review: store credential verifiers rather than raw secrets; use existing opaque-secret, transaction, CSRF, Redis budget and audit primitives where their semantics fit; keep domain relationships in their owning service. Recovery cannot replace ownership verification. Shared clients and Gateway carry accepted transport vocabulary, not domain policy. All lifetimes, recovery channels and user-visible states remain decisions, not selected defaults.

## Delivery and privileged-operation limits

`services/identity/src/infrastructure/otp/webhook-delivery.ts` sends `channel: 'email'`, aborts after three seconds, refuses redirects and non-success responses, and performs no automatic retry. Real external delivery is not proven by that code. Current failure coverage injects a throwing delivery port; it does not exercise the actual adapter's timeout/rejection transport.

The runbook prescribes first-admin setup, while tests seed roles directly in their owning disposable database. No audited production bootstrap command is implemented. Strict V1 bodies remain `{roles}` and `{status}`; expected revision, durable command receipts, scoped grants, last-admin preservation, invitations and step-up are not existing capabilities. CP-D-001 remains a proposal, not permission to silently change V1.

Audit rows are durable and locally allowlisted, but this is not a published revocation event or SQL-enforced immutable audit. Runtime provisioning grants modification rights to owned tables. Current abuse IP uses `socket.remoteAddress`; caller-supplied forwarded IP does not establish trusted ingress. These boundaries need explicit review before guest/recovery/governance extensions.

## Existing executable acceptance

`pnpm acceptance:identity` provisions scoped PostgreSQL/Redis, verifies upgrades/repeated migrations and restricted histories, then runs `tests/identity/api.test.mjs` and `tests/identity/browser.test.mjs`. The browser ingress is an Identity security fixture, not a customer/operator/admin journey. `pnpm acceptance:gateway` includes Gateway API acceptance. Delivery is an injected fixture.

The F006 workflow retains frozen install, generation, build/typecheck, unit tests and pinned Chromium setup. After their compiled prerequisites, `node --test tests/unit/f006-security.test.mjs` covers security primitives. None of these acceptance suites was rerun by this read-only analysis; no historical count certifies a proposed guest capability.
