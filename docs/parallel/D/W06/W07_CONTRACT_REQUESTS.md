## Common proposed schema envelope

Each family proposes an initial `v1` contract for owner/E review; no existing package version implies acceptance. Freeze the exact contract ID, public route/event and package version at the barrier. Require closed request/response/event parsers, explicit required/nullable/unknown fields and examples of rejection. Do not copy another owner's internal model.

| Component | Proposed semantics to approve |
| --- | --- |
| Actor | Authenticated server actor reference, current subject/delegation, action/object/purpose/market scope; guest only through E's accepted bound capability. Never accept actor identity from a client body. |
| Identity/version | Opaque owner IDs, source owner/type/ID, source revision, expected revision for commands, immutable policy/version refs, operation ID and source provenance. Define revision ordering per owner, never global event arrival. |
| Command | Closed action and target input; reason code and permitted audit reference where applicable; expected revision; request operation identity. Family rows add required fields. Unknown action/field is rejected. |
| Receipt/status | Stable operation ref, outcome distinction and owner revision, authorized status lookup, safe failure code, explicit pending/unknown/partial/retained values as approved. Freeze which fields are absent versus null; an acknowledgement is not completion. |
| Event | Authenticated owner producer, event ID/schema version, entity/operation and revision, occurrence time and approved minimal public payload. No private text, evidence bytes, contact data, identity documents or provider secrets. |
| Money | Where applicable, owner-approved exact decimal/minor-unit representation, currency, precision/rounding/tax semantics and immutable price/obligation refs. No floating-point amount, implied currency or D recalculation. Non-financial contracts omit money. |
| Time | UTC instants with explicit market timezone where local schedules matter; owner-defined expiry, as-of and coverage. No guessed duration, retry limit, cutoff, retention or calendar guarantee. |
| Replay | Scope binds actor/delegation, owner action and stable business operation; canonical fingerprint, same-input receipt replay, changed-input conflict, retention/lifetime and expiry behavior frozen by owner. A new key cannot bypass business uniqueness. |
| Failure/recovery | Distinct denied/not-found policy, invalid input, revision conflict, ineligible, unavailable and unknown outcome; bounded deadlines and retry policy. Persist owner progress and reconcile authoritative status after lost response; no blind repeat of money or external delivery. |
| Compatibility | Additive change only where the existing closed parser permits it; breaking shape requires reviewed new version/common base. Freeze deprecation/replay retention and simultaneous provider/consumer coverage. |
| Packages/config | E-owned contracts/event-contracts/api-clients, service/client manifest dependencies, gateway routes/grants and mandatory CI requests. Owners provide typed semantic validators; D does not edit shared files. |

All implementation children require real owner persistence/migrations/constraints, HTTP authorization and service credentials, provider conformance and accepted consumer parsers. Fixtures remain labeled contract fixtures. Broker families need replay, reorder, crash-before-ACK, isolated consumers and projection reconciliation. App consumers need merged providers and actual affected browser journeys. Linux canonical pixels and separate Windows/device interaction are independent gates.
