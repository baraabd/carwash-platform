## Native-library scan coverage correction

Inspecting final image artifact 11089492475 on source 115aa61 showed that its two copied C++ ABI libraries lacked package metadata in the final image. CI was green, but the SBOM omitted libgcc-s1 and libstdc++6. That intermediate green run is not used as the acceptance evidence for this correction.

The isolated candidate run 36700600293 built Identity with Debian 13 libraries from the digest-pinned cc-debian13 donor, retaining their original dpkg records and licenses. Both packages were observed at 14.2.0-19, amd64. Only those two libraries are copied; neither the donor's OpenSSL libraries nor its complete package database are copied. The final base-nossl runtime is preserved. Candidate raw HIGH/CRITICAL/UNKNOWN and secret scanning passed without VEX, and its SBOM identified both ABI packages. Actual Node 24.21.0, bundled OpenSSL 3.5.8, TLS context creation, signature verification and native Argon2 hash/verify succeeded with UID 1000 and networking disabled.

Every real image now requires this native crypto/TLS and package-metadata probe; Identity additionally requires Argon2. The SBOM gate rejects a missing, duplicated, differently versioned or incorrectly identified ABI package, and rejects reintroduced system OpenSSL. Generator technical Dockerfile expectations were updated by hashing its actual rendered source; approved HTML and visual snapshots remain unchanged.

The scope remains Linux amd64 foundation acceptance, not ARM support, a deployed TLS endpoint, production load or whole-application readiness. Recorded Node/OpenSSL versions are execution provenance, not a claim that Trivy inventories every statically bundled component.
