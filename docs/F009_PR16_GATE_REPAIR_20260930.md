Status: implementation record, not a substitute for final-source acceptance.

A separate read-only diagnosis (36698311993) reproduced both findings in the maintained cc-debian13 candidate; refreshing the tag alone was not remediation.

The PR received a separate base-nossl runtime change while this review was in progress. This patch is prepared above the current PR head and preserves that work. It does not claim authorship or acceptance of that runtime change. Final image builds, native runtime loading, vulnerability scans and SBOM records must prove the resulting runtime independently.

This repair runs the repository-pinned Prettier on scripts/ci/image.mjs and tests/unit/f009-security-remediation.test.mjs rather than excluding either file from formatting. It also persists a bounded unfiltered scanner inventory before rejecting a finding or secret, so a failing image stage retains source SHA/tree, run/attempt, runtime/image identity, scanner version, finding metadata and secret counts. Raw secret text and source snippets are not retained.

The existing Power8-only glibc VEX preflight is narrowed to the observed Debian 13.7 amd64 package version and exact package URL. An architecture, distribution, version or identity mismatch remains blocking. The second Trivy VEX scan still has to succeed. New tests explicitly retain both OpenSSL findings, unrelated UNKNOWN findings and secret counts; no threshold or required dependency is removed.

Reference HTML, UI snapshots, business code, database schemas, branch protection and production environments are unchanged by this follow-up. No merge is authorized. The helper prepares source objects only; acceptance requires all new and inherited checks on the final PR commit, including the push analysis rather than PR CodeQL alone. Local container execution was unavailable; the recorded formatter and regression execution used GitHub runners.
