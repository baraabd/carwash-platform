# api-gateway

Stateless Nest HTTP gateway. The allowlisted route contract is
`packages/contracts/src/gateway.ts`; `docs/contracts/gateway.openapi.json` is
generated from that contract. Owners authenticate current principals and enforce
ownership, revisions, service scopes and financial invariants again.

## Browser routes

- `/api/v1/auth/*` forwards Identity's bounded authentication transport.
- `/api/v1/customer/*` provides profile, published Catalog definitions, Booking
  creation/list/detail/change commands and Billing payment/refund views.
- `/api/operator/*` connects the deployed technician client to Identity,
  Workforce, Dispatch, Booking, Media and Billing. A Dispatch cash declaration
  does not constitute a Billing receipt.
- `/api/v1/admin/*` includes the Reporting operations views, Dispatch assignments,
  Booking detail, Communications notifications and existing finance operations.
- Provider notification routes preserve exact bounded bytes; Billing verifies
  the provider signature. They forward no browser or identity credentials.

Unknown paths, extra path segments, encoded traversal, unknown/duplicate query
keys and out-of-range enum values fail closed. The gateway never derives an
origin from the request. Mutations retain the caller's `Idempotency-Key` and a
validated `If-Match` is forwarded only on declared revisioned routes. Errors use
the shared strict API envelope. Retryable refusals retain the command and key;
timeouts and unreadable mutation replies require reconciliation because their
outcome is unknown.

## Runtime wiring

`GATEWAY_UPSTREAMS` is a JSON object mapping the required owners to trusted
origins. Supported owners are `identity`, `customer`, `catalog`, `booking`,
`workforce`, `billing`, `support`, `reporting`, `dispatch`, `communications`
and `media`. Missing owner origins refuse requests; they never fall back to a
fixture. Origins must use HTTPS, except literal loopback HTTP for local tests.
Configure `IDENTITY_ISSUER`, `IDENTITY_AUDIENCE` and the exact browser origins in
`GATEWAY_ALLOWED_ORIGINS`. Keep session keys and service tokens in their owners;
no service credential is exposed to the browser.

The cash flow also requires Billing's `BILLING_DISPATCH_ORIGIN`. Booking's saved
snapshot flow requires the corresponding digest-only grants in
`VEHICLE_SERVICE_CLIENTS` and `CUSTOMER_SERVICE_CLIENTS`; their credentials are
owner-to-owner only and are never Gateway routes.

## Verification and limits

Run `pnpm test:gateway` and `pnpm check:gateway-contract` after building the shared
packages and Gateway. Gateway HTTP tests use explicitly labelled owner doubles.
The P01–P06 business acceptance workflow separately runs real owner persistence,
HTTP and browser suites and records their dependency scope. Frozen design
references are never regenerated by these checks.

Health continues to report `businessReady: false` until complete product release
acceptance. Route availability and green transport tests alone do not certify
checkout, live providers, approved pricing, or production rollout.
