# F001 — فاحص ملكية المصدر ضمن مرشح التأسيس

الحالة: **مرشح تنفيذ محلي، غير مرفوع وغير مقبول كسبرينت كامل**.
المصدر المرجعي: `baraabd/carwash-platform`، فرع `main`، commit
`0d6453fc65b62efd287ad3728930857d930e6601`.

## ما يضيفه هذا الجزء

فاحص TypeScript مستقل وإضافي يعتمد على شجرة تركيب المصدر AST، وليس على مطابقة نصية
لعبارات `import`. يبني رسم اعتماديات لمجلدات الخدمات والتطبيقات والمناطق المشتركة
المسموحة، ويعيد فشلًا صريحًا عند تجاوز الملكية أو تعذر إثبات هدف الاستيراد.
لا يستبدل الفاحص القديم ولا يحذف أي بوابة سابقة.

يتتبع الاستيراد والتصدير وإعادة التصدير واستيراد الأنواع، و`require` وأشكال
`createRequire` المغطاة بالاختبارات، والسلاسل الثابتة بين backticks، وملفات
TS/TSX/MTS/CTS/JS/JSX/MJS/CJS. يفحص أيضًا حقول اعتماديات الحزم الأربعة،
والأسماء البديلة للاعتماديات، و`tsconfig paths` بما فيها الإعدادات الموروثة،
والمراجع بين مشاريع TypeScript، ومسارات `imports` و`exports` الشرطية.

المصادر داخل كل مالك تفحص مستقلة عن `include` و`exclude` في tsconfig.
تستبعد مجلدات المخرجات `dist` و`coverage` و`.turbo`، و`.git` و`node_modules`
فقط من مسح المصدر. لا يسمح بروابط رمزية في شجرة المصدر المملوكة.
هذه بوابة ملكية للمصدر، وليست تدقيقًا للمخرجات المنشورة أو لحزم الطرف الثالث.

## قرارات الملكية في هذا الجزء

التطبيقات الحالية هي `customer-web` و`operator-web` و`admin-web`، والبوابة
`apps/api-gateway`. أبقينا اسم `operator-web` الحالي دون إنشاء تطبيق فني مكرر.
تُقرأ قائمة خدمات البيانات من كتالوج F001 ذي الإصدار 2: تسعة عشر مالك بيانات
وبوابة مستقلة بلا بيانات أعمال. حُدّثت الملكية المستهدفة ولم يُنقل كود الأعمال
أو تُرحّل بيانات تشغيلية. التفصيل في ADR F001 ووثيقة حدود المساهمة.

يسمح بالمناطق المشتركة المسماة صراحة: `event-contracts` و`contracts` و`api-clients`
و`ui` و`design-tokens` و`observability` و`security-kit` و`test-utils`
و`eslint-config` و`tsconfig`. السماح بالاسم لا يثبت أن محتوى الحزمة تقني فقط؛
مراجعة المحتوى البشرية مطلوبة لمنع مكتبة أعمال كبيرة باسم تقني.
الحزم المشتركة تحتاج إصدارًا واعتمادًا معلنًا ومدخلًا عامًا؛ المسارات النسبية
واستيراد الملفات الداخلية لا يتجاوزان هذه القاعدة. الحزم المختبرة كمثال لا تنشئ
أي API أعمال أو خدمة تشغيلية حقيقية.

لا يجوز للخدمة استيراد خدمة أخرى أو تطبيق. ولا يجوز للتطبيق أو البوابة أو الحزمة
المشتركة استيراد تنفيذ خدمة أو عميل قاعدة بيانات. `test-utils` مقيدة بالاختبارات،
ولا يجوز لخدمة استيراد UI. يمنع فحص الرسم وجود دورة اعتماديات بين المالكين.

## أوامر التشغيل بعد تثبيت اعتماديات الجذر

الهدف المثبت في المستودع: Node 24.x وpnpm 10.32.1 وTypeScript 5.9.3.
الاعتماد الجديد للأنواع مقترح بإصدار صريح `@types/node: 24.0.0`.
لم يُثبت هذا الاعتماد في بيئة إعداد الرقعة، ولم يُنتج lockfile مختلق.
يجب تثبيت الاعتماديات، وتحديث lockfile الحقيقي، وبناء وفحص الأمان قبل أي دمج.

```sh
pnpm typecheck:ownership
pnpm test:ownership
pnpm check:ownership
pnpm check:ownership:ci
node scripts/check-design-reference.mjs
node --test tests/design/reference-lock.test.mjs
pnpm verify:foundation
```

الواجهة المباشرة بعد البناء:

```sh
node scripts/check-ownership.mjs --root /path/to/carwash-platform --json
node scripts/check-ownership.mjs --root /path/to/carwash-platform --ci --json
```

رمز الخروج 0 يعني أن نطاق فحص المصدر المحدد اجتاز فقط، و1 مخالفة ملكية/بنية،
و2 فشل إعداد أو تحميل أو عدم مطابقة أدوات CI. لا يوجد خيار لتجاهل الأخطاء.
وضع CI يرفض بيئة غير Node 24.x / TypeScript 5.9.3 بدل تسجيل نجاح بأدوات بديلة.

## حدود هذا التنفيذ وما لم يثبت

أضيف كتالوج الإصدار 2 ومخطط JSON Schema والتحقق الدلالي وهياكل المجلدات
الناقصة وبوابة اكتشاف Workspace. يحتفظ الفاحص بدعم الإصدار 1 للاختبارات
التراجعية فقط؛ بوابة قبول F001 تتطلب الإصدار 2 واكتشاف pnpm الحقيقي.
عدد المالكين في الاختبارات المعزولة يعود إلى بيانات اصطناعية، وليس فحصًا لمستودع حي.

المجلدات الحالية التي لا تحتوي package.json ستظهر كموانع صريحة، لا كنجاح وهمي.
الهياكل والكتالوج الموسع موجودان في المرشح؛ التحقق من تطبيقهما في نسخة كاملة
ومن بناء الأدوات المستهدفة شرط مستقل لم يتحقق بمجرد وجود الملفات.
المدخل العام للحزمة المشتركة يحتاج `exports` أو مدخل `main` قديم واضح؛
لا ينبغي تعطيل هذه القاعدة لتمرير حزمة لم يستكمل هيكلها بعد.

التحليل ليس برهانًا عامًا على كل برنامج JavaScript أو كل محمّل مخصص. الاستدعاءات
الديناميكية المباشرة غير القابلة للتحليل تفشل، لكن تحليل البيانات التعسفي ومحملات
الحزم المخصصة وتحويلات bundler وملفات HTML المضمنة وتنفيذ JavaScript خارجي
خارج نطاق البرهان. لا يثبت الفحص أن خدمة لا ترسل SQL يدويًا عبر الشبكة،
ولا أن أدوار Postgres أو RabbitMQ أو أسرار التشغيل معزولة. هذه تحتاج اختبارات حقيقية.

أضيف تعريف workflow مستقل في `.github/workflows/f001-ownership.yml` داخل المرشح،
مع ترك workflow حماية المرجع الحالي دون تعديل. وجود التعريف ليس رفعًا إلى
GitHub أو تشغيلًا ناجحًا، ولا يجعله فحصًا إلزاميًا في إعدادات حماية الفرع.
لا يمثّل CODEOWNERS أو هذا المستند تفعيلًا لحماية الفروع.

## ترتيب استكمال العمل المتوازي

يملك عامل F001 وحده تعديل ملفات الجذر والكتالوج والفاحص وملف قفل الاعتماديات.
يعمل كل عامل آخر على worktree وفرع مستقل ومسارات خدمته فقط.
تدمج العقود المتوافقة وهياكل الملكية أولًا، ثم الخدمات المستهلكة، ثم التطبيقات.
لا تُدمج إعادة توزيع ملكية البيانات دون خطة ترحيل وتعويض عند وجود حالة محفوظة.
لا تُشارك Prisma client بين الخدمات لتسريع النقل، ولا تُحل العوائق داخل البوابة.

فرع Sprint 0.2 الموجود على GitHub ليس جزءًا من قاعدة هذه الرقعة. لا تُطبق الرقعة
عليه تلقائيًا ولا تُستبدل تعديلاته؛ يلزم تدقيق فروق التأسيس قبل التقاطع معه.
ملفات HTML والتصميم والسياسات المجمدة وCODEOWNERS والفاحص القديم لم تعدّل.
لا أعمال موزعة أو عمليات دفع أو حجز جديدة في هذا الجزء.

## القبول المتبقي لـ F001

تطبيق المرشح الموحد في نسخة كاملة، وتثبيت الأدوات وتوليد ملف قفل حقيقي والتحقق
من البناء والأمان وlint/format واكتشاف pnpm، ثم تشغيل جميع البوابات القديمة
والجديدة ومراجع التصميم على commit نهائي معلوم. قد تكشف هذه الفحوص إصلاحات
إضافية؛ لا يجوز وصف العمل بأنه لا ينتظر سوى النشر.
إلى حين ذلك يبقى الحكم الإجمالي **BLOCKED**، ولو نجحت اختبارات الفاحص المعزولة.
