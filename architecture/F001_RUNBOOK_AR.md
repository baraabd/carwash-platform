# F001 — دليل التطبيق والتحقق

## الحالة والحدود

هذه ملفات تأسيس وحدود ملكية، وليست التطبيقات التجارية الثلاثة. القبول النهائي
يتطلب نسخة Git كاملة، الأدوات المستهدفة، ملف قفل مولد فعليًا، ومخرجات جميع
البوابات على مصدر واحد. لا تعتمد الاختبارات التشخيصية على بيئة أخرى كقبول.

هدف الأدوات: Node `24.x`، وpnpm `10.32.1`، وTypeScript `5.9.3`.
بقية إصدارات الأدوات مثبتة في `package.json`، لكنها ليست شهادة أمان أو تثبيت.
لا تنشئ ملف قفل يدويًا ولا تنسخ ملف Sprint 0.2 وتفترض توافقه.

## تطبيق الحزمة دون المساس بعمل المستخدم

شغّل أداة `APPLY_F001.mjs` الموجودة في حزمة التسليم مع مسار مستودع
`carwash-platform` ومسار worktree جديد غير موجود. الأداة تتحقق من اسم
المستودع، وبصمة الرقعة، وSHA الأساس، والمسارات المسموحة، وحالة الفرع قبل
الكتابة. تنشئ worktree مستقلًا وتطبق الرقعة فقط. لا commit أو push أو merge.
عند إخفاق خطوة تترك الحالة للفحص؛ لا تحذف ملفات المستخدم لاستكمال العملية.

لا تطبق الحزمة فوق رقعة التسليم السابق: الرقعة الجديدة موحدة وتشمل الفاحص
السابق والإضافات. أساسها هو `main` عند
`0d6453fc65b62efd287ad3728930857d930e6601`، وليس فرع Sprint 0.2.

## التثبيت الأول في بيئة متصلة

بعد تطبيق الرقعة وفي worktree الجديد، ومع الأدوات المستهدفة:

```bash
pnpm install --no-frozen-lockfile --ignore-scripts
pnpm build:ownership
pnpm check:foundation
pnpm check:ownership
pnpm test:f001
pnpm lint:f001
pnpm format:f001:check
pnpm exec turbo run build --force
pnpm verify:foundation
pnpm test:design-lock
pnpm audit --audit-level=low
```

هذه أوامر فعلية يجب تسجيل نتائجها؛ إدراجها في الوثيقة ليس ادعاء تنفيذها.
توليد ملف القفل محليًا خطوة أولية، ولا يُعتمد/يُلتزم في Git قبل اجتياز التثبيت
والبناء والفحص الأمني. إبقاء `--ignore-scripts` يمنع تشغيل lifecycle scripts
التلقائية. إن ظهر احتياج حقيقي لسكربت تثبيت، راجع الحزمة والسبب وحدد سماحًا
ضيقًا موثقًا؛ لا تلغِ الحماية على مستوى المستودع كله.

`pnpm format:f001:write` ينسق قائمة الملفات المملوكة لهذا السبرينت فقط عند
اختياره صراحة. لا تستخدم تنسيقًا شاملًا لملفات التصميم القديمة أو المراجع.
أي إخفاق يحتاج إصلاح السبب وإعادة الفحص؛ لا يُستثنى لإغلاق السبرينت.

## بوابة القبول الموحدة

```bash
pnpm verify:f001 --base-ref 0d6453fc65b62efd287ad3728930857d930e6601
```

تسجل البوابة SHA المصدر وحالته ونتيجة كل أمر. تستعمل نسخة فاحص التصميم
المأخوذة من SHA الأساس، وتتحقق قبل الاختبارات وبعدها، وتشغل جميع البوابات
القديمة والجديدة. تستخدم `pnpm install --frozen-lockfile --ignore-scripts`
ولا تولد ملف قفل بديلًا أثناء CI.

قد تنجح فحوص working tree وتبقى النتيجة `BLOCKED` لأن المصدر لم يُثبّت بعد.
بعد المراجعة وإنشاء commit مقصود للملفات المحددة وملف القفل المتحقق منه، أعد:

```bash
pnpm verify:f001 --ci --base-ref 0d6453fc65b62efd287ad3728930857d930e6601
```

لا `ACCEPTED` مع مصدر متغير أو فحص مفقود أو اختبار متخطى/TODO. المخرجات
تُكتب خارج المستودع حتى لا تخفي التغييرات أو تدخل سجلات بيئة في commit.
رفع الفرع وفتح PR يأتيان بعد التحقق وبصلاحية كتابة فعلية؛ لا دمج تلقائي.

## ما لا تغطيه F001

لا تثبت البوابة تسجيل الدخول أو الحجز أو الدفع أو المتصفح أو نشر الخدمات
أو أدوار PostgreSQL أو RabbitMQ ACLs. لا توجد موارد أعمال محمية أضيفت هنا
لتُدّعى لها اختبارات صلاحيات. API/event entries حالات مقترحة غير منفذة.
نجاح البصمات الأصلية يثبت حفظ المرجع، لا مطابقة واجهة React غير منفذة.

## تفسير رموز الخروج

- `0`: نجحت البوابة المعنية؛ القبول الموحد يتطلب مصدرًا نهائيًا نظيفًا.
- `1`: فشل اختبار/قاعدة فعلية.
- `2`: مدخل غير صالح أو متطلب تنفيذ مفقود؛ ليس نجاحًا مشروطًا.

في CI، ملف `f001-ownership.yml` إضافة مستقلة إلى فحص المرجع الأصلي.
صلاحياته `contents: read` فقط. لا يضيف صلاحيات إدارة ولا يتظاهر بأنه branch
protection. غياب ملف القفل أو الأدوات أو المصدر المطلوب يمنع إعلان القبول.
