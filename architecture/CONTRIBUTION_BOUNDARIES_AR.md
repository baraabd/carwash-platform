# F001 — ملكية المجلدات والعمل المتوازي

## مصدر الحقيقة

الكتالوج `architecture/service-catalog.json` هو المرجع الآلي للملكية.
قيمة `owner` معرف مسؤولية منطقي فريد، وليست فريق GitHub أُنشئ فعليًا.
المراجع البشري المسجل حاليًا هو `baraabd`؛ لا نفترض وجود 19 شخصًا أو فريقًا.

| المسار                                  | مسؤولية التعديل                                  |
| --------------------------------------- | ------------------------------------------------ |
| `services/<id>/**`                      | مالك المجال `<id>` وحده                          |
| `apps/customer-web/**`                  | واجهة العميل؛ مرجعها المعتمد لا يتغير            |
| `apps/operator-web/**`                  | واجهة الفني؛ لا إنشاء مسار منافس باسم technician |
| `apps/admin-web/**`                     | واجهة الإدارة؛ لا ملكية أصلية لبيانات الأعمال    |
| `apps/api-gateway/**`                   | النقل والتوجيه وتجميع الردود؛ بلا قاعدة أعمال    |
| `packages/<id>/**`                      | مالك الحزمة التقنية أو العقد المحدد              |
| إعدادات الجذر والكتالوج وملف القفل وCI  | مسؤول دمج واحد في كل دفعة                        |
| ملفات التصميم الأصلية والسياسات المجمدة | خارج صلاحية سبرينت F001                          |

`CODEOWNERS` الأصلي مجمد ضمن حماية التصميم، ولذلك لم يُعدّل. هذه الوثيقة
بديل تنظيمي مسموح في F001، وليست حماية فرع أو شرط مراجعة مُفعّلًا في GitHub.
لا يُدّعى تفعيل branch protection أو منع مدير المستودع من تجاوز القواعد.

## قبل بدء أي worktree

افحص `git status --short --branch` و`git worktree list` و`git stash list` دون
حذف أو تعديل. سجّل SHA الأساس واسم السبرينت والمسارات المملوكة. لا تستخدم
`git reset --hard` أو `git clean -fd` أو force push، ولا تنفذ إعادة تهيئة قواعد
البيانات أو تنظيف Docker عامًّا.

أنشئ فرعًا وworktree مستقلين. ملف الحجز التنسيقي أو وصف PR يحدد المالك
والمسارات والاعتماديات. لا يعمل عاملان بالتوازي على ملف الجذر نفسه أو
`pnpm-lock.yaml` أو الكتالوج. تعديل النطاق المشترك يُمرر إلى مسؤول الدمج.

## ترتيب الدمج

1. تثبيت F001 وقبول مصدره النهائي أولًا، دون دمج تلقائي إلى `main`.
2. التوفيق بين بنية F001 وفرع Sprint 0.2 المنفصل، خصوصًا ملاك البيانات وعدد
   الخدمات. لا تُدمج إعدادات عشر خدمات فوق كتالوج 19 مالكًا دون تحقق.
3. دمج الإضافات المتوافقة للعقود، ثم تنفيذ الخدمة المالكة وترحيلاتها، ثم
   المستهلكين والواجهات. تغيير العقد الكاسر يحتاج إصدارًا جديدًا وفترة توافق.
4. يجمع مسؤول الدمج تغييرات الاعتماديات ويولّد ملف القفل مرة واحدة، ثم يعيد
   جميع بوابات القبول على SHA الأخير. نجاح فرعين منفصلين لا يثبت نجاح دمجهما.

## حدود الاستيراد والكتابة

الخدمة لا تستورد تنفيذ خدمة أخرى أو مستودعها أو نموذجها الداخلي أو Prisma
الخاص بها، ولو كان الاستيراد من النوع `import type`. التطبيق والبوابة يتصلان
عبر عقود/عملاء API بإصدار. لا تنقل منطق الأعمال إلى حزمة مشتركة لتجاوز الفحص.
الاستعلام الإداري يذهب إلى الخدمة المالكة أو Reporting؛ لا حساب قاعدة بيانات
يقرأ جداول الجميع. التسمية الصحيحة في JSON ليست دليلًا على عزل قواعد فعلي.

لا تُخفى الإخفاقات بحذف اختبار، أو `.skip`، أو TODO، أو تعطيل typecheck، أو
تغيير المرجع البصري. عند تعارض فرعين تُصلح الطبقة المالكة ثم تعاد البوابات؛
لا يُستبدل الملف كاملًا بما يمحو عمل فرع آخر.
